# СБП по ссылке и выбор языка

Контракт: https://pay-provider.casa/docs/, OpenAPI пользователя «Payment API.yaml» (14.11.2026). Работает только `method=qr`. Метод `card` платёжной системы не вызывается. Клиент открывает `payment_url`, где поставщик переводит его в приложение банка. Изображения QR в мини-приложении не генерируются.

## Язык и способы оплаты

`/start` всегда показывает три inline-кнопки в порядке «Русский», «English», «中文». После выбора бот отправляет меню разделов. Выбор хранится по Telegram ID и применяется также к мини-приложению. Кнопка «Язык меню» позволяет выбрать заново; профиль приложения также сохраняет выбор. До первого выбора используется язык Telegram.

Для русского языка карта из исходного Telegram-чата имеет первый приоритет. Если подходящей действующей карты нет, показываются СБП и USDT. Для остальных языков доступны только криптопереводы; проверка выполняется сервером, а не только интерфейсом. IP и страна подключения на способы оплаты не влияют. Эта же логика используется для пополнения баланса.

## Настройки и ограничения

В «Оплаты → СБП по ссылке» можно включить/выключить СБП и вручную выбрать MC9, MC10 или MC27. По умолчанию выбран MC9. Автоматического переключения на другой MC при ошибке нет. Действующие платежи сохраняют выбранный при создании метод.

Названия MC не являются внутренними ID: на момент подключения MC9 имеет `qr_method_id=3`, MC10 — `7`; MC27 отсутствует в списке доступных методов. Соответствие определяется по названию из свежего `GET /methods/`. Для выдачи разрешены только эти три MC; вьетнамские методы отклоняются дополнительно по названию и описанию. Отсутствующий метод не предлагается. Минимум и максимум проверяются по актуальному списку до создания каждого платежа, включая границы. Лимиты и описания отображаются в админке. Банковские ограничения показываются покупателю.

Срок не фиксируется как 10 или 15 минут. Таймер и крайнее время берутся только из `expires_at`. Если поставщик не указал срок, приложение направляет к сроку на платёжной странице без вымышленного таймера.

## Ключи и вебхук

В runtime `.env` задаются `PAY_PROVIDER_API_KEY` и `PAY_PROVIDER_WEBHOOK_SECRET`. Они не входят в Git и публичные ответы API. Адрес уведомлений:

`https://kyc.ggsellik.click/api/webhooks/pay-provider`

Его нужно зарегистрировать у владельца платёжной системы: OpenAPI не содержит метода для самостоятельной регистрации URL. `whsec_…` — секрет подписи, а не адрес вебхука. До поступления уведомлений и при их задержке статус проверяется через API.

Вебхук проверяется по HMAC-SHA256 от `X-Timestamp + "." + raw_body`, с безопасным сравнением подписи и допуском 5 минут. ID доставки дедуплицируется в SQLite. После быстрой записи возвращается 200; тяжёлая проверка идёт из очереди. Перед выдачей товара запрашивается фактический статус платежа через API и сверяются внешний ID, order_id, customer_id, RUB, ожидаемая и полученная сумма. Возврат браузера на success_url не подтверждает оплату. Чек и ручная кнопка Gateway также не подтверждают СБП.

## Повторы, поздние оплаты, чеки

Создание сначала резервирует локальный ID. При тайм-ауте POST выполняется поиск по `order_id`, без слепого повторного создания. Неопределённая попытка блокирует смену способа до выяснения. Действующую ссылку СБП отменить по API нельзя: повтор доступен только после завершения/истечения и подтверждения покупателя, что деньги не отправлены. Поздний success обрабатывается и для старых попыток. Остатки и баланс изменяются один раз на всю цепочку попыток. Недоплата и недостаток товара передаются на ручную проверку.

Чек, загруженный в мини-приложение, сохраняется локально и имеет две независимые очереди доставки: в Gateway получателю квитанций и в `/payments/{id}/receipt/` платёжной системы. Разрешены PDF/JPG/PNG/WebP до 10 МБ и до 5 чеков. Для чеков СБП Gateway не показывает кнопку ручного подтверждения денег. Ошибка передачи провайдеру не удаляет сохранённый файл; менеджер получает уведомление. Чеки, загруженные на внешней форме провайдера, невозможно скачать через данный API, поэтому для передачи в обе системы чек нужно прикреплять в мини-приложении.

Фоновый опрос использует пакетный список и проверку отдельных зависших попыток, в том числе до 48 часов после их создания. Подписанные вебхуки принимаются и позже. Запросы ограничены общим бюджетом 100/мин ниже лимита провайдера 120/мин. Активные запросы методов объединяются без постоянного хранения списка. Длительные операции провайдера не выполняются внутри SQLite-транзакций и не блокируют обработку стопов карт.

Проверки: `node --test server/*.test.mjs`, `npm test`, `node scripts/qa-sbp.mjs`, `node scripts/qa-gateway.mjs`, `node scripts/qa-usdt.mjs`. Все платёжные POST в проверках идут в подменённый API. На боевом ключе выполняется только чтение доступных методов: тестовые неоплаченные ссылки могут отключить MC из-за ограничения конверсии.
