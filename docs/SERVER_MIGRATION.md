# Перенос действующего магазина

Основной адрес: `https://kyc.ggsellik.click/`. Основной бот: `@verif_claudebot`, поддержка: `@phiKYC`. Старый бот и `https://kyc.kraken892.rest/` сохраняются как дополнительные входы в ту же базу. Администратор определяется прежним подтверждённым Telegram ID; замена контакта поддержки не передаёт оператору права владельца.

## Данные

Переносится SQLite целиком, включая каталог с текущими ценами, отзывы и их модерацию, ожидающие даты публикации, прямые ссылки, посетителей, заказы, квитанции, баланс, журнал событий и состояние шлюза. `bootstrap-production.mjs` не используется для замены действующих данных. До переноса создаются первоначальная онлайн-копия и финальный снимок после остановки исходного экземпляра. Секреты и базы остаются в закрытых резервных копиях вне Git.

`server/migrate-instance.mjs` применяется только к копии базы и не запускает ботов. Он проверяет отсутствие активных переводов, сохраняет каталог побайтно, меняет только основного бота и контакт оператора, шифрует токен прежнего бота исходным BOTS_ENCRYPTION_KEY и сохраняет его дополнительной воронкой. ID владельца, отзывы, платежи и балансы не меняются. При смене получателя квитанций прежняя привязка ID сбрасывается; новому оператору нужно нажать «Старт» в `@GatewayReqBot` со своего аккаунта.

## Порядок переключения

1. Сохранить начальную базу через SQLite backup API, `.env`, текущий release и конфигурацию собственного Nginx vhost. Скачать закрытую копию вне Git.
2. На целевом сервере зафиксировать ID и время запуска всех существующих контейнеров, хеши конфигураций Nginx и HTTP-ответы действующих сайтов.
3. Подготовить отдельный проект Docker Compose `fikus`, порт только `127.0.0.1:8787`, каталог `/opt/fikus-miniapp` и vhost только для `kyc.ggsellik.click`. Выпустить отдельный сертификат webroot, не меняя сертификаты остальных сайтов.
4. Проверить тестовый снимок на целевом сервере без запуска Telegram workers. Публично этот тестовый снимок не публиковать. Сравнить хеш каталога и сохранённые записи.
5. Дождаться окончания текущих переводов. Остановить только исходный контейнер fiKUS, снять финальную базу, перенести её и применить миграцию к копии. До старта нового экземпляра старый шлюз должен быть остановлен: один Telegram-токен не должен опрашиваться одновременно с двух серверов.
6. Запустить новый экземпляр и проверить HTTPS, каталог, число отзывов, заказы, баланс, чтение источника реквизитов и состояние обоих магазинных ботов. Тестовые сообщения в источник реквизитов запрещены.
7. Переключить только `/api/` старого vhost на HTTPS нового сервера, оставив старый frontend и домен совместимыми. На новом сервере `PUBLIC_ORIGIN_ALIASES=https://kyc.kraken892.rest` разрешает запросы только с этого дополнительного точного origin.
8. Проверить неизменность остальных vhost и контейнеров. Оставить исходные данные и снимки для отката, отключив автоматический перезапуск старого контейнера fiKUS.

## Дальнейшие релизы

Скрипты `deploy/activate.sh` и `deploy/activate-frontend.sh` берут домен из `FIKUS_HOST` либо PUBLIC_ORIGIN закрытого `.env`. Шаблон `deploy/kyc.nginx.conf` содержит `__FIKUS_HOST__` и заполняется перед установкой. ACME webroot — `/var/www/fikus-acme`. Скрипты сверяют конфигурации и контейнеры остальных проектов до и после публикации.

Основное Mini App нового бота включается владельцем в BotFather с новым HTTPS URL. Кнопки `web_app` и «Каталог» работают с новым адресом через Bot API; основной Mini App и медиа блока описания требуют настройки в BotFather.

При откате сначала остановить новый экземпляр, затем восстановить исходную конфигурацию Nginx и запустить старый контейнер. Не запускать два шлюза одновременно. Если на новом сервере уже появились новые покупки или пополнения, прежде нужно перенести актуальную базу обратно; нельзя откатывать деньги и заказы старым снимком.
