# фиКУС: интерфейс покупки и заявки

Изменения касаются UI, описаний и контрактов frontend. Бот, платёжный коннектор, доставка и проверка прав остаются на стороне подключаемой панели.

## Готовые сценарии

| Сценарий | Экраны |
| --- | --- |
| Фиксированная цена | Карточка → корзина → проверка состава и условий → отдельный заказ |
| Цена по запросу | Карточка → параметры → отдельная заявка → ожидание предложения магазина |
| Поддержка | Вопрос по заказу / предложению → подготовленный текст с контекстом → копирование / переход в Telegram |
| Возврат к выбору | Карточка → предыдущая категория, результаты поиска или избранное с восстановленной прокруткой |

В «Моих заказах» объединены покупки и заявки, есть фильтры активных и завершённых. Прежние записи `demo` / `demo-request` читаются и показываются как ожидание оплаты / согласования.

## Объявления

В `Product.offer` добавлены поля:

- `result`: что получит покупатель;
- `includes`: состав предложения;
- `requirements`: что требуется до оформления;
- `region`: совместимость региона;
- `term`: период или срок действия;
- `fulfillment`: способ и срок выполнения;
- `refund`: условия гарантии, отмены и возврата.

Поля редактируются через «Редактор каталога → товар → Условия и содержание объявления» и экспортируются вместе с каталогом. Новая валидация импорта проверяет типы полей. Старые каталоги совместимы; отсутствующие поля заполняются шаблоном без изменения цен, валют, порядка, скрытых групп и авторских описаний. Пустые сроки и регионы отображаются как требующие подтверждения до оплаты.

Тексты Claude оформлены по структуре присланных референсов, но не копируют взаимоисключающие условия разных продавцов. Не перенесены неподтверждённые «100 000 продаж», дата допустимой регистрации, перечень принимаемых документов, автоматическое оформление 24/7 или универсальная комиссия 0%. Версии моделей не фиксируются в объявлениях: возможности тарифов связаны с [официальной страницей Claude](https://claude.com/pricing).

В интерфейсе использовано согласованное позиционирование «100% гарантия. Доводим до согласованного результата». В карточке рядом есть переход к условиям. Для Claude гарантийная область описана отдельно от KYC, блокировок и решений Anthropic. Универсальный полный возврат или конкретное удержание не заявляются: предоставленные примеры противоречат друг другу. До коммерческого запуска владелец должен утвердить конкретные условия для каждого предложения.

## Контакты и расписание

«Профиль → Контакты и условия магазина»: Telegram, часы, ожидаемое время ответа, описание магазина, общая политика отмены/возврата. Это методы `StoreAdapter.loadShop()` / `saveShop()`.

Указанный пользователем `@duriv` сохранён как временный контакт и помечен в интерфейсе. По присланному изображению: Пн 13:00–23:00, Вт 11:00–23:00, Ср–Пт и Вс 12:00–23:00. Суббота и часовой пояс не были указаны; они не выдумываются. Срок ответа не задан.

Копирование обращения не отправляет сообщение. Приложение не принимает пароли, коды входа, сессионные ключи и документы.

## Контракт статусов для друга

`OrderStatus`:

| Значение | Что показывает UI |
| --- | --- |
| `awaiting_details` | Нужны уточнения, действие «Уточнить данные» |
| `awaiting_quote` | Стоимость и срок ещё не согласованы |
| `awaiting_confirmation` | Готовое предложение магазина: стоимость, срок, явное подтверждение покупателя |
| `awaiting_payment` | Состав, суммы, переход к оплате при наличии подключённого URL |
| `processing` | Работа выполняется, согласованный срок из `estimatedCompletion` |
| `completed` | Инструкция из `result`, обращение по проблеме |
| `failed` | Причина из `issue`, связь с поддержкой |
| `cancelled` | Завершение без выполнения, возможность выбрать предложение снова |

Общие необязательные поля `OrderProgress`: `updatedAt`, `demo`, `note`, `events: {at,text}[]`, `estimatedCompletion`, `paymentUrl`, `result`, `issue`, `quoteTotal`, `quoteCurrency`. Локально создаваемые записи имеют `demo:true`: магазин их не получает, деньги не списываются. UI не позволяет оплату или подтверждение таких записей, даже если в данных задан URL. Для рабочего подтверждения нужны `awaiting_confirmation`, цена, срок и серверный метод `acceptQuote(id)`; он возвращает обновлённую заявку.

Для покупок сохранён снимок состава: `productId`, название, подзаголовок, цена, валюта, количество и условия предложения на момент оформления. RUB и USD складываются раздельно через `currencyTotals`; нет фиктивной конвертации. `total` остаётся `null`, если в заказе несколько валют. Для предложения по заявке используются `quoteTotal` и `quoteCurrency` (по умолчанию RUB).

Платёжный коннектор возвращает актуальный заказ и HTTPS `paymentUrl`, ставит `demo:false`. Подтверждение оплаты и переход к выполнению определяются сервером, не callback браузера. URL с `javascript:`, `data:` и HTTP UI не открывает. Сервер должен проверять цену/остатки, права пользователя, подпись Telegram и идемпотентность создания заказа.

Предпросмотр всех восьми состояний доступен из профиля владельца, маршрут `#/order-preview/awaiting_payment`. Примеры явно помечены и не попадают в реальные заказы.

## Вход из объявления

- Локально: `?ref=klod&product=claude-pro-cdk`.
- Telegram: `startapp=klod__claude-pro-cdk` — конкретное предложение и бренд Claude на всех экранах.
- `startapp=product__capcut-pro-7d` — конкретное предложение с обычной логикой бренда.

ID из параметров валидируется. Ссылка открывает карточку, ничего не покупает автоматически. Закрытые предложения остаются недоступными.

## Читаемость и устойчивость

Подписи и условия увеличены, основные кнопки и быстрые действия получили более крупные зоны нажатия. В карточке закреплено действие над нижней навигацией. Поля формы используют стабильные доступные имена, отдельные ошибки, `aria-invalid` и фокус на первой ошибке.

Черновики заявок, комментария к заказу и обращения сохраняются локально. Ошибка оформления не очищает корзину или комментарий. Прокрутка каталога восстанавливается при возврате. Есть отдельное состояние ошибки загрузки с повторной попыткой.

Проверки: `npm test`, `npm run test:ui` / `npm run test:commerce`. Скриншоты и результат — `qa/commerce/`. Это локальная проверка Chromium, не приёмка настоящего Telegram WebView или оплаты.
