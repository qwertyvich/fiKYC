# Магазин одного продавца: актуальный сценарий

## Покупка

Каталог → корзина → проверка состава → сообщение в личный чат продавца. Текст содержит каждую позицию, артикул, вариант, количество, стоимость строки, раздельные итоги RUB/USD и комментарий. Покупатель сам отправляет сообщение и согласует оплату и выполнение с продавцом. Открытие чата не создаёт оплаченный заказ, не очищает корзину и не меняет остатки.

Услуги по запросу: карточка → параметры → предпросмотр сообщения → тот же личный чат. Параметры сохраняются для возврата и перезагрузки.

Контакт пока пустой. Старый временный `duriv` также трактуется как заглушка. До указания рабочего контакта в профиле владельца доступны предпросмотр и копирование сообщения, исходящий переход отключён. Контакт задаётся в «Контакты и условия магазина → Telegram продавца».

Используется официальный формат [`https://t.me/<username>?text=<draft_text>`](https://core.telegram.org/api/links#public-username-links). Внутри Telegram вызывается `openTelegramLink`, в браузере — обычная ссылка. Текст длиннее 4096 символов можно скопировать и отправить частями. Автоматической отправки нет.

## Баланс покупателя

В профиле показан предпросмотр баланса, 0 RUB и 0 USD. Кнопка пополнения проверяет сумму и подготавливает запрос продавцу. Подготовка/копирование сообщения не зачисляет средства. При оформлении можно попросить оплату с баланса — это пожелание добавляется в текст заказа.

Реального кошелька и серверного реестра операций ещё нет. Для запуска нужен аутентифицированный источник остатков и подтверждённых зачислений/списаний с идемпотентностью. Нельзя считать клиентское открытие ссылки, возврат из Telegram или содержимое localStorage подтверждением оплаты. Без этой интеграции UI не изменяет баланс и не объявляет оплату завершённой.

## Отзывы и показатели

В каталоге и карточке показаны средняя оценка, число отзывов и число покупателей конкретного предложения. Нет отдельных аккаунтов и рейтингов продавцов. Отзывы сохраняются в браузере, допускают одно редактируемое локальное мнение на предложение и не отмечаются как проверенные покупки. Средняя оценка считается только по отзывам этого предложения. Пустое состояние не выдаёт фиктивную оценку.

Покупателей задаёт владелец в редакторе объявления по данным магазина. Неизвестное значение — «—», явный ноль — «0». Демо-заказы, отзывы, переходы в чат и запросы пополнения не увеличивают этот показатель. Для общей статистики нужен серверный подсчёт уникальных покупателей подтверждённых заказов.

## Проверки

- `npm test`: правила каталога, совместимость старых данных, покупатели, текст заказа, безопасные ссылки, суммы пополнения.
- `npm run test:commerce`: сценарии покупки/пополнения и отзывов в изолированных браузерных контекстах. Сообщения в Telegram не отправляются.
- `npm run test:services`: миграция ассортимента, формы услуг, мультивалютный заказ и редактор.
- `npm run build`: TypeScript и итоговый `dist/`.

Этот сценарий заменяет создание локального демо-заказа из корзины, описанное в ранних `UX-HANDOFF.md` и отчётах. Просмотр старых заказов и демонстрация их состояний сохранены.
