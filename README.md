# фиКУС · Telegram Mini App и панель владельца

Цифровой магазин на React + TypeScript + Vite. Панель в том же дизайне: Geologica, мягкие карточки, лайм фиКУС и отдельное оформление Claude. Каталог, настройки, отзывы, прямые ссылки и аналитика хранятся на сервере в SQLite.

## Что можно настроить

- **Обзор:** посетители, сессии, нажатия, просмотры, корзина и активное время в карточках; графики по дням и путь к оформлению.
- **Товары:** все тексты и условия, цена/валюта/остаток, формат продажи, параметры заявки, иллюстрация, плашка, поиск; дублирование и быстрое/массовое скрытие.
- **Лента:** порядок перетаскиванием или стрелками, отдельно порядок и видимость категорий.
- **Доступ:** кнопка панели скрыта от покупателей; сервер проверяет права отдельно. Чёрный список по username/Telegram ID показывает заблокированным пользователям экран технических работ.
- **Отзывы:** очередь проверки, публикация/скрытие, ответ магазина. Изменения видны между устройствами.
- **Прямые ссылки:** генерация только в админке, случайные коды, названия источников, счётчики, отключение; открытие нужного товара в боте.
- **Аналитика:** периоды и фильтр товара, часы активности, статистика по предложениям, сессии и лента действий, CSV.
- **Оплаты:** актуальные карты из Telegram, лимиты, стопы открытых оплат, 15 минут на перевод, квитанции и подтверждение менеджером.
- **Настройки:** контакты, часы и время ответа, общая информация и гарантия, тема, тексты витрины, объявление, Telegram-параметры, отзывы и сбор событий.

Описание работы и метрик: [docs/ADMIN.md](docs/ADMIN.md).

## Локальный запуск

Нужны Node.js **22.18+** и npm.

```bash
npm ci
npm run setup:local
npm run server
```

В другом терминале:

```bash
npm run dev
```

Магазин: http://127.0.0.1:5174/

Панель: http://127.0.0.1:5174/#/admin/overview

`setup:local` создаёт `.env` со случайным паролем. Пароль панели — `ADMIN_PASSWORD`. Существующий `.env` команда не изменяет. `.env` и `data/` исключены из Git. API работает на `127.0.0.1:8787`; Vite перенаправляет к нему `/api`.

Username бота, имя Mini App и Telegram ID владельцев можно заполнить в настройках позже. Бот-токен задаётся только в окружении сервера (`BOT_TOKEN`). При настройке Telegram-входа сервер проверяет подпись initData, срок и ID администратора. В production парольный вход отключён: панель доступна только подтверждённому продавцу из Telegram через HTTPS. Username продавца задаётся в настройках либо в SELLER_TELEGRAM_USERNAME. При первом входе он привязывается к стабильному Telegram ID.

Вход Claude: `/?ref=klod`. Прямые ссылки товаров создаются в разделе «Прямые ссылки»; Main Mini App или именованное приложение предварительно настраивается в BotFather.

## Проверки

```bash
npm test                 # правила каталога, порядка, тем, локализации, оформления
npm run test:server      # авторизация, SQLite, ссылки, отзывы, аналитика, чёрный список
npm run build            # TypeScript и dist/
npx playwright install chromium
npm run test:admin       # изолированный сервер и браузеры владельца / покупателей
npm run test:access      # production-доступ, привязка username, техработы и блокировки
```

`test:ui`, `test:commerce`, `test:seller` и `test:reviews` запускают актуальный общий браузерный набор. Старые `qa-*.mjs` сохранены как материалы исходной версии; новые проверки не меняют рабочую базу и не отправляют сообщения реальным пользователям.

Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` для установленного Chromium. Отчёт и скриншоты сохраняются в игнорируемой папке `qa/admin/`.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/App.tsx` | Витрина, маршруты, корзина, подключение событий |
| `src/admin/` | Защищённая панель, редакторы, графики, модерация |
| `src/api.ts` | Общий транспорт API |
| `src/analytics.ts` | Пакеты событий и активное время карточки |
| `src/review-store.ts` | Серверные отзывы |
| `src/domain.ts` | Типы, поиск, порядок, валидация |
| `src/catalog.ts` | Начальный ассортимент для новой базы |
| `server/` | HTTP API, SQLite, авторизация, метрики и тесты |
| `data/` | Локальная SQLite-база, не попадает в Git |
| `docs/ADMIN.md` | Метрики, доступ, ссылки и размещение на сервере |

Production-сборку `dist/` раздаёт сам backend (`npm start` всегда включает защищённый production-режим). Для сервера с другими ботами подготовлены Dockerfile и Compose: отдельный порт на loopback и отдельный volume. Настройка существующего nginx и HTTPS описана в ADMIN.md; публикация требует адреса сервера и домена.

## Границы интеграции

Оплата на карту, квитанции, ручное подтверждение поступления и история оплат подключены: [настройка шлюза](docs/PAYMENTS.md). Учёт баланса пока не подключён; вместо выдуманного нулевого остатка баланс отображается как неизвестный, с запросом продавцу. Корзина оформляет серверный заказ с оплатой на карту; услуги по запросу готовят сообщение продавцу; открытие чата не означает отправку, оплату или выполнение. Старые демо-заказы остаются в локальном браузере. Графики показывают действия, не выручку. Посетители определяются по анонимной cookie браузера, поэтому число браузеров не равно точному числу людей.

Товар и его категория должны быть включены, чтобы карточка открылась, включая прямые ссылки. Ссылка не отображается в витрине и может быть отключена; открыть её может любой получатель кода.

Исходный ассортимент и цены сохранены для настройки владельцем. Источники изображений, шрифтов и палитр: [ассортимент](docs/ASSORTMENT.md), [логотипы](docs/logo-sources.json), [палитра Claude](docs/references/CLAUDE-PALETTE.md), [Clawd](docs/CLAWD-ASSETS.md). Старые UX-отчёты описывают исходную поставку; текущий серверный сценарий — в ADMIN.md.

Демонстрационное распределение покупателей 30–190 и оценок 4,9/5,0 в соотношении около 80/20 доступно только продавцу через «Товары → Демопоказатели». Оно явно помечено, не сохраняется в каталог и не публикуется покупателям.
